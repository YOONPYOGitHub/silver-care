# 온담 · Silver Care

어르신이 자신의 생활·건강·복지를 직접 묻고 선택하는 한국어 AI 도우미다.
가족을 돌보는 보호자도 이용할 수 있다. 기본은 텍스트 모드이며 음성 모드에서 말로 대화를 이어갈 수 있다.

서비스: <https://ondam-e4b60458.koreacentral.cloudapp.azure.com>
소스 저장소: <https://github.com/YOONPYOGitHub/silver-care> (비공개)

## 답변에 사용하는 자료

| 경로 | 자료 | 사용 방식 |
| --- | --- | --- |
| 임베딩 검색 | AI Hub 의학 원천, 보건복지부 매뉴얼, MedlinePlus, 기관·서비스 안내 | 관련 문서를 검색해 사실 근거로 전달·인용 |
| 임베딩 검색 | 복지로 중앙부처·장기요양기관 검색 API의 수집 응답 | 수집 시 문서화·임베딩한 스냅샷을 검색. 채팅 중 API를 호출하지 않음 |
| 임베딩 검색 | AI Hub 감성 대화·의학 QA | 대화·질문 참고 사례. 사실 근거로 인용하지 않음 |
| 실행 시 API 조회 | 질병관리청 건강정보 21개 주제 | 질문에 맞는 본문을 조회·발췌해 답변 근거로 전달·인용 |
| 평가 전용 | QA·대화 holdout, AI Hub 어르신 음성 표본 | 온라인 검색·답변 근거로 사용하지 않음 |

**검색 인덱스에는 지식 5,759개와 사례 6,762개, 합계 12,521개의 문서 벡터가 있다.**
평가 전용 1,721개와 질병관리청 API 본문은 임베딩 대상이 아니다.
문서 임베딩과 질문 임베딩은 `silvercare-embedding` 배포의 512차원 벡터를 사용한다.
이는 모델 재학습이나 지식증류가 아니다.

AI Hub만이 전체 지식 출처는 아니다. 운영 문서는 각 출처를 구분해 설명한다.
자료별 수량과 호출 시점은 [데이터 흐름](docs/rag.md)을 참고한다.

## 요청 흐름

```text
질문
 ├─ 응급 표현 감지 → 고정 도움 안내
 └─ 개인정보 패턴 최소화
     ├─ 검색어 확장 → 질문 임베딩 → 지식·사례 하이브리드 검색
     └─ 관련 건강 주제 → 질병관리청 API 본문 조회·문단 선별
         ↓
     사실 근거와 참고 사례를 구분해 답변 생성
         ↓
     답변·인용 출처·건강 안내·공식 원문 보기
```

질병관리청에는 콘텐츠 ID와 서버 인증키만 보내며 질문·대화 이력은 보내지 않는다.
답변 모델에는 질문·최근 대화·검색 자료·관련 API 본문 발췌가 전달된다.
정확한 순서·제한·오류 동작은 [RAG·API](docs/rag.md)에 있다.

## 사용자 기능

- 가입·접속 코드 없이 이용한다. 요청 크기·빈도·동시 처리 제한을 적용한다.
- 주제 카드는 본인 관점의 질문을 전송한다. 보호자 예시는 별도로 펼쳐 선택한다.
- 대화·주제·설정 메뉴는 같은 페이지의 영역으로 이동한다. 데스크톱 보조 패널은 긴 대화에서도 사용할 수 있다.
- 큰 글씨, 모바일 세로 카드, 키보드 조작, 출처 링크와 원문 열람을 제공한다.
- ‘글로 대화’는 입력·수정 후 전송한다. 앱의 받아쓰기 버튼은 없으며 휴대폰 키보드의 받아쓰기는 사용할 수 있다.
- ‘말로 대화’를 선택하면 마이크 권한을 요청한다. 말끝 감지 또는 ‘말 마침’으로 음성을 인식해 질문을 자동 전송하고, 답변을 읽은 뒤 다음 말을 듣는다. 두 모드는 같은 대화·검색 근거를 사용한다.
- 음성 모드는 한 사람씩 말하는 턴 단위 대화다. 실시간 스트리밍 인식이나 AI와의 동시 발화 방식은 아니다. 듣는 중에는 ‘말 마침’·‘잠시 멈춤’, 답변 준비/재생 중에는 ‘답변 멈추고 말하기’를 사용할 수 있다.
- 듣는 중에는 마이크 주변 원이 부드럽게 퍼지고 실제 입력 음량에 따라 막대가 반응한다. 답변 중에는 스피커로 바뀌며, 처리 중·일시정지는 각각 다른 아이콘과 문구로 표시한다. 기기의 동작 줄이기 설정에서는 애니메이션을 사용하지 않는다.
- 답변을 읽는 동안은 녹음하지 않는다. ‘잠시 멈춤’, 텍스트 전환, 새 대화, 화면을 벗어날 때 음성 처리를 취소한다. 인식 오류·연결 실패는 표시하고 음성 대화를 일시정지한다.
- 음성 모드와 ‘이 답변 듣기’는 읽기용 텍스트를 공통으로 사용한다. 화면의 굵은 글씨·인용·출처는 유지하고, 음성에서는 서식 기호·인용 번호·별도 출처 목록을 제외한다. 주의사항·숫자·단위·확인 질문은 읽는다.
- 한 번에 처리하는 음성에는 2분·4MB 안전 상한을 적용한다. 무음 약 3초가 말끝 기준이며, 입력 없이 30초가 지나면 일시정지한다. 전체 대화를 2분으로 제한하는 것은 아니다. 인식 결과는 화면에서 확인하고 필요하면 텍스트로 전환해 수정한다.
- 119 카드는 모바일에서 전화 앱을 열고 일반 PC에서는 전화 이용 안내창을 연다. 자동 신고·위치 전송은 하지 않는다.
- 대화 이력은 현재 브라우저 탭의 메모리에 유지된다. 답변에는 최근 12개 이전 메시지와 현재 질문을 전달한다. 새로고침·새 대화로 지워지며 서버 상담 이력이나 장기 기억으로 저장하지 않는다.
- 진단·복약 변경·검사 시행·지원 자격을 확정하지 않는다. 출처 표시가 정확성·최신성을 보증하지 않는다.

## 로컬 실행

Python 3.12+, [uv](https://docs.astral.sh/uv/), 모델·검색 접근에 필요한 Azure 자격이 필요하다.
[환경변수 예시](.env.example)를 참고하되 실제 환경 파일을 덮어쓰지 않는다.
예시 파일의 연결값은 비어 있으므로 실제 endpoint·배포명·리소스·키를 비공개 `.env`에 설정한다.

```bash
uv sync --group dev
az login
APP_ENV=development PUBLIC_ORIGIN=http://127.0.0.1:8000 TRUSTED_PROXY=false \
uv run uvicorn silvercare.app:create_app --factory --host 127.0.0.1 --port 8000
```

명령은 설정된 기능만 활성화한다. 운영 하이브리드 검색 설정을 로컬에서 사용하려면
[연결 실행 절차](docs/operations.md)를 따른다. `PUBLIC_ORIGIN`은 브라우저 주소와 같아야 한다.

## 검증

```bash
uv run pytest -q
uv run ruff check silvercare tests
uv run mypy
node --check silvercare/static/app.js
```

프론트엔드 회귀 테스트와 JavaScript 문법 검사에는 Node.js가 필요하다.
Node.js가 없으면 해당 pytest가 건너뛰어질 수 있으므로 전체 검증 환경에서 설치 여부를 확인한다.
검색 적중률, 실제 모델의 출처 인용, 음성 인식 측정은 별도 평가다.
명령·결과 위치·표본 한계는 [운영 가이드](docs/operations.md)를 참고한다.
실제 모델·검색·음성 호출에는 사용량 비용이 발생할 수 있다.

## 운영 경계

앱은 AKS에서 공개 HTTPS로 제공하며 모델·검색·음성에는 Workload Identity로 접근한다.
질병관리청 키만 서버의 Kubernetes Secret으로 주입한다. 키·원본·정제본은 이미지에 넣지 않는다.
Azure 리소스가 한국에 있어도 `GlobalStandard` 모델의 국내 추론을 보장하지는 않는다.
단일 노드·앱·엣지·검색 replica 구성은 고가용성 구성이 아니다.

[.gitignore](.gitignore)는 인증정보·원본·처리 결과·런타임 상태를 제외하고,
[.dockerignore](.dockerignore)는 빌드 입력을 애플리케이션과 의존성 파일로 제한한다.
제공처 HWP·Word 가이드는 로컬 참고용이며 Git에 포함하지 않는다.
업로드 대상과 추적 중인 비밀값의 주의사항은 [Git 확인 절차](docs/operations.md#8-git-업로드-전-확인)에 있다.
문서 변경은 서비스 재배포나 데이터 재적재를 요구하지 않는다.
