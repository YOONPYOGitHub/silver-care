# 데이터·임베딩·API·답변 처리

자료 확인 기준일: 2026-11-14(KST). 자료 수와 평가 수치는 명시한 처리 보고서를 따른다.
실행 방법은 [운영 절차](operations.md), 리소스와 모듈은 [아키텍처](architecture.md)를 참고한다.

## 1. 용어와 처리 경로

**API는 자료를 받는 인터페이스이고, 임베딩은 텍스트를 검색용 벡터로 바꾸는 처리다.**
API 자료도 수집·문서화·임베딩할 수 있다. 모든 API를 채팅 중 호출하거나 모든 자료를 임베딩하는 것은 아니다.

| 구분 | 처리 시점 | 자료 | 임베딩 | 답변에서의 역할 |
| --- | --- | --- | --- | --- |
| 파일·문서 수집 | 운영자 수집·발행 | AI Hub 의학 원천, 공식 매뉴얼·건강정보·이용안내 | 문서 벡터 저장 | 사실 근거 검색·인용 |
| API 응답의 문서화 | 운영자 수집·발행 | 복지로 중앙부처·장기요양기관 검색 스냅샷 | 문서 벡터 저장 | 사실 근거 검색·인용. 실시간 조회는 아님 |
| 참고 사례 구성 | 운영자 corpus 준비·발행 | AI Hub 감성 대화·의학 QA | 문서 벡터 저장 | 대화 말투·질문 의도 참고. 사실 인용 금지 |
| 질문 검색 | 건강·일반 대화 요청 | 검색어 확장과 현재 질문 | 요청마다 질문 벡터 생성 | 지식·사례 검색에 같은 벡터 사용 |
| 건강정보 상세조회 | 관련 질문 또는 원문 열람 | 질병관리청 API의 허용된 21개 주제 | 하지 않음 | 본문 문단을 생성 근거로 전달·원문 열람 |
| 평가 | 평가 명령 | holdout·음성·합성 시나리오 | 온라인 문서 벡터 없음 | 품질 점검. 온라인 사실 근거 아님 |

임베딩·API 조회·RAG는 모델 재학습이 아니다.
사용자 질문에 맞는 근거를 모델 입력에 넣어 답변하며, 가중치나 KD checkpoint는 변경하지 않는다.

활성 설정은 `data/processed/expanded/release.json`,
자료 수는 `data/processed/expanded/inventory.json`과 발행 보고서를 기준으로 한다.
각 행은 원본 파일 수나 원문 문서 수가 아닌 **검색 문서·청크 수**다.
원본 파일별 레코드·스키마·통계는 [원본 분석](data-analysis.md)에 있다.

| 원천 | 수 | 사용 방식 |
| --- | ---: | --- |

QA의 전체 질문·선택지·라벨 정답은 사례 문서에 보존한다.
생성 모델에는 질문 줄기와 해석 유형만 전달한다.
틀린 설명을 고르는 문제의 정답을 의료 사실로 취급하지 않는다.

**지식과 사례 합계 13,293개의 문서 벡터를 사용한다.**
동일한 입력의 벡터는 캐시에서 재사용하고 제목·본문이 바뀐 문서는 다시 임베딩한다.
평가 전용 **1,721개**는 정규화한 질문·대화의 안정적인 SHA256 기준으로 약 20% 분리하며 인덱싱하지 않는다.
`Validation`이라는 원본 split 이름만으로 전체를 배제하지 않는다.
이 분할이 모든 의미·유사 문장 중복을 제거한다는 뜻은 아니다.

## 3. 파일·문서 준비와 벡터 발행

[catalog.json](../data/catalog.json)은 AI Hub의 파일과 역할을 등록한다.

| 데이터셋 | 파일 ID | 역할 |
| --- | --- | --- |
| 71874 | 556339 | 학회 가이드라인 원천 |
| 71875 | 556377 | 온라인 의료정보 원천 |
| 71874 | 556353 | 예방의학 QA |
| 71875 | 556388 | 내과 QA |
| 86 | 66048 | 감성 대화 |

- 아카이브는 파일시스템에 직접 풀지 않고 읽는다. 동일 ZIP part는 내용 확인 후 중복 제거한다.
- 파일당 16MB·압축 해제 총량 256MB를 적용하며, 충돌하는 중복·누락 part·심볼릭 링크를 거부한다.
- 원천 문서는 본문·출처 표기·record ID·기재 연도를 보존하고 Unicode·공백·민감정보 패턴을 처리한다.
- 약물·검사·치료라는 단어만으로 문서를 거부하지 않는다. `general`/`clinical`은 내용 태그이지 임상 안전성 인증이 아니다.
- `audience`는 `general`/`self`/`caregiver`/`provider`다. 담당자 업무 문서를 이용자가 직접 해야 할 일로 바꾸지 않는다.
- 의학 원천은 1,600자/180자 겹침, 외부 지식은 1,600자/160자 겹침으로 청킹한다. 범용 manifest 경로의 기본값은 1,000자/120자다.
- 임베딩 입력은 `title + "\n" + content`다. 배포 `silvercare-embedding`, 모델 `text-embedding-3-small`, 차원 512를 사용한다.
- 캐시는 `모델 배포명 + 차원 + 입력 텍스트` 해시별 SQLite다. 같은 입력은 임베딩을 재사용하고 메타데이터 변경은 문서 갱신으로 처리한다.
- 발행은 변경 문서 업로드와 발행 대상의 누락 ID 삭제를 수행한다. 전체 corpus를 실행 중인 인덱스에 바로 덮어쓰는 절차는 [운영 가이드](operations.md)에서 금지한다.

원본·처리본은 `data/raw/`, `data/processed/`에 보관하며 Git·앱 이미지에서 제외한다.
자동 정리·분류는 전문가 검토나 재사용 권한에 대한 인증이 아니다.

### 의료 보강 v6

이번 보강의 목표는 **근거가 있는 환자교육**이다. 개인별 진단·처방·약물 변경이나
전 진료과의 전문 상담을 인증하지 않는다. 청크 수를 질병 수나 완결된 진료지침 수로 세지 않는다.
AI Hub 학회 원천은 영상의학·비뇨의학·신경외과·통증 등에, 온라인 원천은 ADA 자료에 편중돼 있다.
QA·감성 대화는 의료 사실의 근거로 승격하지 않는다.

| 우선 영역 | v6 적용 | v6 당시 한계·v7 연계 |
| --- | --- | --- |
| 욕창·인지 저하 | 실제 XML 제목 `Pressure Sores`, `Mild Cognitive Impairment` 수록 | v7에서 VA 상처 관리 본문 추가. 섬망 감별의 전문 검토는 별도 |
| 순환기·비뇨기·신장·내분비 | 심방세동, 전립선비대증, 신부전, 갑상선질환, 빈혈 등 환자교육 추가 | 국내 진료지침·복합질환·고령자 적용 조건 확인 필요 |
| 종양·통증 | 주요 암·암 치료 개요와 비약물적 통증 관리 추가 | 개인별 항암·진통제 선택·용량은 대상 아님 |
| 다제약물·상호작용 | FDA 노인 약물 안전과 의약품 목록 작성·갱신 본문 추가 | v7에서 기전 표와 9성분 라벨/표 보관. 완전한 상호작용 DB나 용량 계산기는 아님 |
| 노쇠·근감소·삼킴·영양·완화의료 | 기존 자료와 공개 후보의 범위를 조사 | v7에서 WHO 기능·이동·영양·통합 돌봄 추가. 전용 진단 지침·의료인 검토는 별도 |

MedlinePlus의 기존 정확 제목 목록에는 실제 XML에 없는 `Bedsores`, `Frailty` 등이 있었다.
`Pressure Sores`, `Coping with Chronic Illness`, `Chronic Bronchitis` 같은 실제 제목으로
수정하고 진료과별 주제를 확대해 **110개에서 155개**를 수록했다.
수집 보고서는 요청했으나 없는 제목도 명시한다. 존재하지 않는 `Frailty` 제목을 추가했다고 주장하지 않는다.
우선 주제 49개의 한글 검색 제목은 프로젝트의 메타데이터 번역이며 영어 원문 본문을 대체하지 않는다.

재사용은 [NLM 정책](https://medlineplus.gov/about/using/usingcontent/)에 따른 건강 주제의
public-domain **summary**로 한정한다. A.D.A.M. 백과사전·ASHP 약물 문서·이미지·외부 링크의
내용까지 공개 이용이 허용됐다고 확대하지 않는다.

FDA 자료와 원문 표시 날짜는 다음과 같다.

- [5 Medication Safety Tips for Older Adults](https://www.fda.gov/consumers/consumer-updates/5-medication-safety-tips-older-adults): 2024-02-15.
- [Create and Keep a Medication List for Your Health](https://www.fda.gov/consumers/consumer-updates/create-and-keep-medication-list-your-health): 2025-01-08.
- [FDA 재사용 정책](https://www.fda.gov/about-fda/about-website/website-policies#linking):
  별도 표시가 없는 FDA 본문은 public domain이다. 수집 시 해당 정책과 개별 본문을 확인한다.

FDA는 고정된 두 URL의 제목·본문 범위·실제 날짜를 검증하며, 별도 저작권 표시가 있으면 실패한다.
이미지·영상·탐색·관련 자료는 제외하고 원래 절의 문맥을 유지한다.
각 청크에 출처·원문 날짜·미국 환자교육이며 한국 처방 기준이 아니라는 구분을 보존한다.
이 날짜를 2026년의 새 임상 검증일로 바꾸지 않는다.

추가 후보인 NIA 자료는 자동 접근 차단으로 본문을 확인하지 못했다.
CDC STEADI는 의료인용 기능·낙상 평가 자료가 포함돼 환자교육과 구분해야 하며,
NIDCD 삼킴장애 PDF 등은 오래된 판의 최신성·개별 이용조건 확인이 남았다.
원문 접근·권한·판본이 확인되지 않은 후보는 이번 corpus에 넣지 않았으며 접근 제한을 우회하지 않는다.

독립적인 의료인 검토 상태는 **미실시**다. [답변 평가 질문](../data/audience-evaluation.json)을
검토 대기 목록으로 사용해 원문 일치, 중요한 누락, 한국 적용 가능성, 위험 신호,
임의 진단·복약 변경 방지, 쉬운 표현을 각각 검토해야 한다.
자동 검색·문구·인용 검사는 이 검토를 대신하지 않는다.

### 전문 근거 보강 v7 · 비상업적 이용

운영자가 2026-11-14에 확인한 비상업적 이용을 전제로 위 지식 **591개 청크**를 추가했다.
노쇠·근감소 관련 기능 저하와 복합적인 건강 문제는 WHO 자료로,
상처 관리는 VA 자료로, 약물 상호작용·신기능 관련 조건은 FDA/openFDA 자료로 보강한다.
다섯 범주를 보강한 것이지 해당 분야의 모든 지침·약물을 완비했다는 뜻은 아니다.
모든 새 자료는 `audience=provider`, `risk_level=clinical`, `review_status=automated`다.
의료인용 평가·처치·약물 조절을 이용자의 자가 시행 지시로 바꾸지 않는다.

**WHO:** [ICOPE 2판](https://www.who.int/publications/i/item/9789240103726)은 공개 페이지 날짜가
2025-09-22이고 PDF 저작권은 2024년이다. 두 날짜를 임상 검증일로 혼동하지 않는다.
168개 PDF 쪽(본문 인쇄 쪽수와 다름)의 SHA256
`7addb319b953fe56306e093148431f606bb58feaed3b6557293f93cfa108f5eb`를 고정한다.
통합 계획·이동 기능·영양 관련 지정 본문만 열별로 읽고 이미지·감지한 표·열 경계를 가로지르는 영역은 제외한다.
원문 전체나 모든 흐름도·평가 도구를 복원한 자료는 아니다. 제외 영역은 수집 보고서에 명시한다.

[WHO 이용정책](https://www.who.int/about/policies/publishing/copyright)에 따라
원문은 CC BY-NC-SA 3.0 IGO, 프로젝트의 발췌·정제·번역·요약 부분은 CC BY-NC-SA 4.0으로 구분한다.
WHO가 작성·검증·추천한 서비스로 표시하지 않으며 영어 원문이 우선한다.
인용 응답의 `reuse_notice`와 `license_url`은 유지한다.

### 검색 개선 v8

v7의 원문·청크 수를 바꾸지 않고 최종 집계본에 자료 유형·원문 언어·국가 범위·분야·부모 키·
청크 순번·제한된 약명 연결을 추가했다. 지식은 6,531개, 부모 원문은 5,899개다.
`source_type`은 환자교육·임상 지침·약물 기전·제출 라벨·의학 데이터셋·복지 안내·기관 검색·문의 안내를 구분한다.
영문 원천 1,000개는 원문으로 유지한다. 검색어는 한국어와 필요한 영어를 병기하고 같은 512차원 임베딩을 쓴다.

`CONTEXTUAL_RETRIEVAL=true`일 때의 동작은 다음과 같다.

- 보수적인 질문 범위 계획을 사용한다. 의료·복지가 함께 있으면 둘 다 허용하고,
  목적이 불명확하면 검색 범위를 임의로 좁히지 않는다. 이는 진단 모델이나 완전한 의도 분류기가 아니다.
- 자료 종류는 확인한 원천 ID·역할에서 정한다. 의료인용 자료를 무조건 배제하지 않고 질문과 관련된 근거로 사용한다.
  국가 범위는 원문의 적용 맥락이며 국내 허가사항 확인을 대신하지 않는다.
- 명시적으로 인식한 성분·브랜드가 있으면 그 성분에 연결된 라벨을 허용한다.
  확인하지 못한 약으로 대체하지 않으며 불명확한 병용 질문은 일반 안전 자료와 약명 확인으로 다룬다.
- 분야 후보를 최대 12개, 우선 자료 유형 후보를 최대 6개 검색한다.
  서로 다른 부모 근거를 최대 6개 선택하며 복합 질문은 해당 분야 후보가 있으면 각 분야를 우선 포함한다.
- 각 선택 근거의 앞뒤 한 청크를 한 번의 제한된 원문 조회(최대 18개)로 가져온다.
  같은 원문·URL·자료 유형·국가·언어·독자·날짜·이용조건인지 확인하고,
  부모별 최대 3청크·3,600자 이내에서 원래 순서와 정확히 겹치는 텍스트를 결합한다.
  예산이 부족하면 이웃 청크 전체를 제외하며 조건문을 임의의 문자 위치에서 자르지 않는다.
  이것이 길고 복잡한 원문 전체나 모든 임상 조건을 복원한다는 뜻은 아니다.
- URL만으로 중복 제거하지 않는다. 같은 FDA 표의 다른 약물 행, 같은 라벨의 다른 절은 독립적인 부모다.
  원문 조회 실패·메타데이터 불일치 때는 검색 오류로 알리고 조용히 앵커만 사용하는 성공 응답으로 숨기지 않는다.
- 명시적인 일상 대화·인사이며 사실 질문이 아니면 검색어 확장·임베딩·근거/사례 검색·건강 API를 생략한다.
  응급 감지는 이 분기보다 먼저 실행한다. 의료 질문이 함께 있거나 의도가 불명확하면 검색 경로를 유지한다.
- QA 사례는 의료 시험·문항·객관식 등 명시적인 질문 예시 목적에만 붙인다.
  일반 복약·진료 질문에 시험 문제를 기본 첨부하지 않으며 사례가 사실 근거가 되는 것은 아니다.

표준 의료용어 대응표는 선택된 근거에 해당 영문 표현이 있을 때만 모델에 전달한다.
`nonvalvular atrial fibrillation`은 `비판막성 심방세동`을 먼저 유지하며,
쉬운 말로 풀면서 의학적 범위를 임의로 바꾸지 않는다.
영문 근거도 한국어로 설명하고 수치·단위·적응증·제형·AND/OR·예외·근거 불확실성을 보존하도록 지시한다.
기전 표의 빈칸은 안전함이 아니고 근거 불충분은 효과 없음·사용 금지가 아니다.
용어 대응표는 새로운 의학적 사실의 근거가 아니며 의료 번역·임상 검증을 대신하지 않는다.

정량 표를 직접 조회하는 도구와 개인별 용량 판단은 이번 변경에 포함하지 않는다.
원본 라벨 표·셀 구조는 그대로 별도 보관하며 기존 온라인 제외 범위를 유지한다.

```text
요청 파라미터: TOKEN=<서버 인증키>, cntntsSn=<허용 콘텐츠 ID>
```

- 현재 질문의 명시적 표현과 검증한 구어체·동의어로 최대 3개 주제를 연결한다. `사레`, `음식이 목에 걸리는 느낌`, `연하곤란`은 기존 삼킴 주제로, `혈압약·감기약`, `다른 약과`는 기존 복약 주제로 연결한다. 저혈압만 말한 경우 고혈압 주제로 연결하지 않는다. 제한된 후속 질문만 최근 사용자 주제를 참조하며, 생성된 검색어에서 새 질병을 진단하거나 API 승인 ID를 늘리지 않는다.
- 본문 절 제목·문단의 질문 핵심어 일치도로 주제당 최대 3개 발췌, 최대 4,800자를 선택한다.
- 이 발췌를 `official_api` 사실 근거로 생성 모델에 전달한다. 문서 임베딩이나 Search 업로드는 하지 않는다.
- 원문 보기와 답변 생성은 최대 32개·1시간 서버 메모리 캐시를 공유한다. 원문 본문을 디스크에 저장하지 않는다.
- 질병관리청에는 질문·대화 이력 대신 콘텐츠 ID와 인증키만 보낸다. 질문·이력·발췌는 답변 생성 서비스에서 사용하며 `store=false`다.
- HTTP 성공·`S001`·ID·제목·UTF-8 XML·본문·크기를 검증한다. XML DTD/entity·리다이렉트를 거부한다.
- 이미지·영상·표·스크립트·외부 이미지 URL·참고문헌을 발췌에서 제외한다. 표를 평탄화한 값으로 의료 판단을 안내하지 않는다.
- 같은 절 ID의 연속 텍스트 문단은 한 절로 표시한다. 원문 보기에는 전체 자료 링크와 출처·이용조건을 표시한다.
- 조회 시각은 문서 개정일·임상 검증일이 아니다.
- 답변에 필요한 API 조회가 실패하면 503으로 알린다. 만료 캐시나 무근거 답변으로 실패를 숨기지 않는다. 원문 열람만 실패한 경우 표시된 대화는 유지하고 재시도/원문 링크를 제공한다.

`노인 운동` ID 6758은 정상 코드지만 본문이 비어 있어 허용 목록에서 제외한다.
API 서버 호환성·키 설정은 [운영 절차](operations.md)에 있다.

### 승인 목록과 이용 범위

사용자 제공 가이드 `docs/openApi(guide).hwp`는 로컬 참고용이며 Git에 포함하지 않는다.
[공식 OpenAPI 안내](https://health.kdca.go.kr/healthinfo/biz/health/portalUseGuidance/hlthinsReqst/hlthinsReqstMth.do?index=3)와
가이드는 상세조회 형식을 설명하며, 가이드에는 전체 ID 목록 API 명세가 없다.
공개 카탈로그 스냅샷은 844개(내부 콘텐츠 ID 673개·외부기관 참조 171개)다.
이는 개인 계정의 승인 목록이나 구현한 21개 주제 수와 다른 개념이다.
외부기관 링크를 질병관리청 API로 조회할 수 있다고 가정하지 않는다.

사용자가 보고한 API 승인·활용 요청에 따라 본문을 답변에 사용한다.
[공개 저작권 정책](https://health.kdca.go.kr/healthinfo/biz/health/useGuidance/cpyrhtPolicy.do)의
제4유형과 실제 승인 범위는 별도로 적용되며, 구현이 상용화·대량 재배포 권한을 부여하는 것은 아니다.
AI Hub 자료도 다운로드 승인·공개 답변 활용·처리 위치 조건을 구분한다.

## 6. 검색과 답변의 실제 동작

1. 응급 위험 표현이면 119/112/109 도움 안내를 반환하고 검색·API·모델을 호출하지 않는다.
2. 질문·최근 사용자 발화의 개인정보 패턴을 처리한다. v8의 명시적인 일상 대화 분기는 사실 근거 검색 없이 답하며, 그 외에는 현재 질문과 최근 사용자 질문 최대 2개를 구분해 검색어를 확장한다.
3. 현재 질문을 보존한 한국어·영어 검색어를 임베딩한다. 질문 벡터 하나를 지식·대화·QA 검색에서 공유한다.
4. Search의 BM25와 HNSW/cosine 벡터 검색(`k=50`)을 RRF로 결합하고 지식에 의미 재순위화를 적용한다. v8은 위 분야·유형·부모 문맥 선택을 적용한다. 최종 지식은 최대 6개, 대화 사례는 2개, 명시적인 의료 문항 요청의 QA 사례는 2개다.
5. 질병관리청 주제가 있으면 API 발췌를 추가하고 `PREFER_OFFICIAL_REFERENCES=true`에서 먼저 배치한다. v8 부모 근거는 최대 3,600자, API 근거는 최대 4,800자다. 기능 플래그가 꺼진 이전 검색 경로는 문서 단위 2,200자 제한과 기존 공식 안내 선호 동작을 유지한다.
6. 사실 근거, 대화 사례, QA 질문 줄기를 구분한 JSON과 현재 시스템 지침·대화 이력으로 답변을 생성한다.
7. 인용 번호가 실제 제공한 근거 범위 안인지 검증한다. 인용한 근거만 출처 링크로 반환한다. 인용 번호 검증은 각 문장의 의학적 정확성 검증이 아니다.
8. 답변 아래에는 AI 한계와 필요한 의료 안전 핵심을 합친 `display_notice` 하나를 표시한다.
   API의 `notice`·`medical_caution` 원본 필드는 호환성과 검증을 위해 유지한다.
   자동 정리본·전문가 미검토·인용 근거 없음 같은 해당 답변의 추가 정보는 통합 안내에도 보존한다.
   원문 보기 카드는 유지하되 별도 반복 안내 문장은 표시하지 않는다.

`queryLanguage`는 보내지 않는다. 지식과 사례 벡터는 `stored=false`·비노출이며 검색에만 사용한다.
Search가 설정되지 않은 개발 모드는 검색 결과가 없고 화면에 일반 대화 모드로 표시된다.
질병관리청 키가 설정되어 있으면 관련 건강 질문의 API 근거 기능은 별도로 동작할 수 있다.

`dataset_knowledge`의 수록 출처·record ID·기재 연도는 원문 URL 확인이나 임상 검증을 뜻하지 않는다.
AI Hub 인용 링크는 데이터셋 안내일 수 있고, `official_api` 링크는 실제 국가건강정보포털의 콘텐츠 원문이다.
사례가 사실 근거로 승격되거나 어르신이 보호자라고 임의 가정되지 않도록 시스템 지침과 평가를 적용한다.
모델 제공자의 `content_filter` 거절은 답변으로 대체하지 않고 `422 / safety_refusal` 오류로 표시한다.
안전 필터를 끄거나 거절을 정상 의학 답변으로 집계하지 않는다.

### 출처·권리 고지와 답변 이용 안내

자료별 긴 권리 고지는 ‘이용 안내’ 안에서 확인한다. 인용된 고지 텍스트와 라이선스 링크만
브라우저 세션에 중복 없이 모으며 질문이나 답변 이력을 별도로 저장하는 기능이 아니다.
WHO 원문의 출처·원래 라이선스·가공본 라이선스·번역/가공 고지·비추천 고지는 모두 유지한다.
답변의 출처 번호·제목·원문 링크는 그대로 표시한다.

표준 의료 안내는 다음 하나의 문단으로 표시한다.
“AI 답변은 참고용이며 오류가 있을 수 있어요. 답변만으로 진단·복약 변경·검사 여부를 결정하지 말고 의료진과 상의해 주세요.”
별도의 사용자 정의 의료 주의는 임의로 줄이거나 버리지 않는다.
공식 원문 카드를 열었을 때 나오는 원문별 설명·이용조건은 해당 자료의 정보이므로 계속 제공한다.
입력창 아래에는 AI 서비스라는 사실과 출처 위치를 안내하며 같은 의료 경고를 반복하지 않는다.
이번 표시는 RAG 자료·인덱스·검색 기능·답변 생성 프롬프트를 변경하지 않는다.

### 답변의 분량과 설명 수준

시스템 프롬프트는 [azure.py의 SYSTEM_PROMPT](../silvercare/azure.py)에 정의하며,
요청마다 검색 근거와 함께 모델의 `instructions`로 전달한다.
질문의 복잡도·이용자가 요청한 설명 수준·대화 맥락에 맞춰 답변의 분량과 구성을 정한다.

- 연락처나 단순 사실만 묻는 질문에는 직접 답하고 불필요한 설명을 늘리지 않는다.
- 여러 조건·비교·절차·이유를 묻는 질문은 요청한 항목과 관계를 빠짐없이 설명한다.
- 자세한 설명을 요청하면 단계·적용 조건·이유·구체적인 예시를 포함한다.
- 쉬운 말과 읽기 편한 문장을 사용하되, 짧은 문장을 위해 필요한 설명을 생략하지 않는다.
- 근거 없는 수치·조건을 덧붙이거나 같은 내용을 반복해 분량을 늘리지 않는다.
- 요약 요청에도 중요한 조건·예외·의료·응급 안전 안내는 보존한다.

텍스트·음성 모드에 같은 정책을 적용하며 음성용으로 설명을 별도 요약하지 않는다.
모델 요청의 `max_output_tokens=1300`은 출력 토큰 상한이며 글자 수나 항목 수 제한이 아니다.
평가는 내용·인용·안전 조건을 검사하고, 길이 상한이 필요한 시나리오만 `max_characters`를 지정한다.
단순·복합·상세 설명 요청은 [설명 수준 평가 시나리오](../data/answer-detail-evaluation.json)로 점검한다.

### 대화 맥락과 음성 출력

질문 전송에는 현재 질문과 최근 이전 메시지 최대 12개를 사용한다.
이력은 현재 브라우저 탭 메모리에만 있으며 성공한 질문·답변을 합쳐 보통 6쌍을 유지한다.
검색어 확장은 그 이력 중 최근 사용자 질문 최대 2개를 참조한다.
새로고침·새 대화로 이력을 지우며 서버에 장기 기억을 저장하거나 이전 대화를 요약해 유지하지 않는다.

텍스트·음성 모드가 같은 `/api/chat`과 근거·이력을 사용한다.
음성은 답변 수신 후 `/api/speech/synthesize`를 호출하며,
화면 답변과 별도로 서식·출처 목록을 제외한 읽기용 본문을 만든다.
출처는 화면에서 확인하고, 음성으로는 의학적 주의·119 안내·숫자·단위·확인 질문을 유지한다.
이 과정은 답변 근거를 바꾸거나 모델을 재학습하는 처리가 아니다.
